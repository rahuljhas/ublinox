5Business rules: decisions made

Where the spec said "decision required", this is what was chosen.

RuleQuestionStatusDecision
Order statusesAllowed statuses and transitionsPartialAn order is created only when checkout succeeds, so it has a single state. Cart: OPEN → CHECKED_OUT, exactly once.

How it works

6Checkout flow

POST /carts/{id}/checkout with header Idempotency-Key. Source: backend/src/services/checkoutService.ts.

1Claim key

Done → replay order. Running → 409.

2Lock cart

No edits during checkout.

3Lock items

Coupon + products, sorted: no deadlock.

4Validate

Open cart, stock, coupon; price in cents.

5Await payment

The only point other requests can run.

6Commit

Stock, coupon, order, cart in one block, no await.

7Release

In finally; next shopper starts at 4.

Why locks in single-threaded Node? Without them, two shoppers both pass step 4 (stock = 1), both await payment, and both commit: stock −1. The lock makes the second shopper wait until the first has committed, so its step 4 sees stock = 0.
